# Stripe coverage

Source: Stripe's OpenAPI spec (stripe/openapi, `spec3.json`, API version 2026-09-30.endive), generated by
`bun scripts/openapi-actions.ts stripe`. 606 operations are actions, plus `download_file_contents`. Benchmark: Composio's
Stripe toolkit (435 tools), checked with `.claude/skills/new-integration/coverage.ts`. Action names follow Composio's
wherever one means the same call.

## Deliberately left out

| What | Why |
| --- | --- |
| 6 deprecated operations (customer bank accounts and cards lists, issuing authorization approve/decline) | Stripe marks them deprecated; `payment_methods` covers the first group |
| The `expand` parameter | On every call; it swaps ids for whole objects and makes answers very large. Ask for the object itself instead |
| Composio's `get_monthly_recurring_revenue` | A figure it works out, not an API call; subscriptions list gives the numbers |
| v2 event destinations (`list_v2_core_events`, `update_event_destination`...) | In Stripe's separate v2 spec; webhooks here use v1 |

## Auth

| Method | Status |
| --- | --- |
| Secret key or restricted key, pasted | done |
| Stripe Connect OAuth | not built; it's for platforms acting on other businesses' accounts, not one business's own |

## Triggers

All 269 events Stripe can report, including Composio's 40 under the same names (the event with dots as underscores),
by webhook (`triggers.ts`): one endpoint per connection. Stripe shows an endpoint's signing secret only when it's
created, so we hold no secret: an event counts only when Stripe, asked on this connection's key, confirms it. Setting:
`customer`. A restricted key needs Webhook Endpoints write and Events read.

## Actions

Generated, one per operation in Stripe's spec, grouped as Stripe groups them. Reads run without asking, except
`find_secret` and `list_secrets`, which can show a stored secret. `create_preview_invoice` changes nothing, so it runs
without asking.
