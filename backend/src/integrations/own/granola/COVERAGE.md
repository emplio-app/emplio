# Granola coverage

Source: Granola's OpenAPI spec (docs.granola.ai/api-reference/openapi.json) and its webhooks guide
(docs.granola.ai/webhooks), read 2026-11-24 and generated by `bun scripts/openapi-actions.ts granola`. Every operation
in the spec is an action (21). Not run against a real Granola account yet: every call and webhook is tested with fetch faked.

Composio has no key-based Granola toolkit, only "Granola MCP" (sign-in through Granola's hosted MCP server), so there
are no Composio names to keep.

## Deliberately left out

| What | Why |
| --- | --- |
| Writing notes (new notes from a transcript, renaming, private notes, folders) | Not in Granola's REST API. Granola's MCP server has them (create_meeting_note_from_transcript, update_meeting_title, update_private_notes, create_folder, add_note_to_folder...) but signs in with OAuth only, not a key |
| Granola Chat, recipes, templates, the agent brief | MCP only, same reason |

## Hand adjustments (scripts/openapi/granola.ts)

- GET /v1/analytics has no operationId in the spec: named get_workspace_analytics.
- search_notes and search_transcripts are POSTs that only read, so they run without asking.

## Auth

| Method | Status |
| --- | --- |
| API key (desktop app → Settings → Connectors → API keys; Business or Enterprise plan), sent as Bearer | done |
| Workspace API key (admins: Settings → Connectors → Workspace API keys) | done, same box; webhooks use the "workspace" scope for it |
| OAuth | None in the REST API. Granola's MCP server (https://mcp.granola.ai/mcp) signs in with OAuth and dynamic client registration (mcp-auth.granola.ai/oauth2/register, checked by curl 2026-11-24), so a later "Sign in with Granola" could go through own/mcp-app.ts the way Plaud does. Nothing registered |

Analytics need an analytics key, the audit log an Audit key, and legal holds an admin's key on Enterprise; with an
ordinary key those actions answer Granola's own refusal.

## Triggers (all by webhook)

| Trigger | Granola event |
| --- | --- |
| note_ready | note.generated |
| note_edited | note.edited |
| note_shared | note.access_granted |

One webhook endpoint per connection, with every event its automations need, made with scopes personal + public (falling
back to workspace, then each alone, for keys that can't have both). Granola shows the signing secret only when the
endpoint is made, so it is sealed (AES-GCM under ENCRYPTION_KEY) into the endpoint's own address,
/webhooks/app/granola/<connection>/<sealed secret>, and nothing is stored. Signatures are Standard Webhooks (v1, HMAC
of id.timestamp.body), and deliveries older than 5 minutes are refused. Deliveries carry only the note id, so the note
(without its transcript) is read with the connection's key before the automation sees it. Filter: folder_id (the
note's folder or that folder's parent). Webhooks need a Business or Enterprise plan; the error says so.

Nothing is polled: every change Granola reports has a webhook, and the API has no other changes to list.
