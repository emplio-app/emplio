# Zoho Books coverage

Source: Zoho's own OpenAPI files (zoho.com/books/api/v3/openapi-all.zip, generated 2026-11-09 by `bun scripts/openapi-actions.ts zoho_books`). Every operation in them is an action.

## Left out

| What | Why |
| --- | --- |
| Reports, journal templates and journal document deletion (Composio's get_financial_statement, get_detailed_general_ledger, get_account_transaction_report, list_journal_templates, delete_journal_document, delete_journals, get_template) | Not in Zoho's published API; Composio's must be undocumented calls. Add them if Zoho publishes them |

## Sign-in

Sign in with Zoho only (no key). Scope: `ZohoBooks.fullaccess.all`: the per-module scopes in the docs don't cover items, categories and the newer modules, and this one does. Tokens last an hour and are renewed by `zohoOAuth`.

Every call needs `organization_id`: when it's left out, the login's only organisation is used; with several, the error lists them so the caller can say which. The list is cached for 10 minutes per login. `check` labels the connection with the organisation name(s).

## Hand adjustments

- Zoho's spec gives defaults for fields like tax_treatment; they are stripped, so nothing is sent that wasn't asked for.
- `sort_order` added next to every `sort_column` (A or D), which Zoho takes but doesn't list.
- `organization_id` added to `email_sales_receipt`, where the spec forgot it.
- Three reporting tag calls (mark_tag_option_active, mark_tag_option_as_inactive, get_options) are written by hand: the spec's paths hold a regular expression where the id goes.
- Failures sent with a 200 become errors; a dead login (401 except scope errors, or INVALID_TOKEN) marks the connection expired.
- `preview_invoice_with_coupons` is a POST that only reads, so it runs unasked.

## Triggers (polled, polls/zoho_books.ts)

new_invoice (customer_id, status filters), customer_changed (`<id>:<last_modified_time>`, new_only option), payment_received (customer_id). Each check looks at the newest 200. Composio has none for this app.
