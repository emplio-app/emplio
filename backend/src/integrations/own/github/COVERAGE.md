# GitHub coverage

Source: GitHub's OpenAPI description (github/rest-api-description, api.github.com), generated by
`bun scripts/openapi-actions.ts github`. 1,177 operations are actions, plus `get_raw_repository_content`. Plain `git`
runs through `git-proxy.ts` on the same login. Benchmark: Composio's GitHub toolkit, checked with
`.claude/skills/new-integration/coverage.ts`.

## Deliberately left out

| What | Why |
| --- | --- |
| 56 App and enterprise operations | They only answer to a GitHub App or an enterprise's own login, never to a person's token |
| 38 deprecated operations (Classroom, older Codespaces access, security managers) | GitHub marks them deprecated |
| `POST /markdown/raw` | Plain-text body; `render_a_markdown_document` does the same |
| Discussions, sponsors, star lists, custom GraphQL queries | GraphQL only; the actions are REST |

## Triggers

All 46 of Composio's, under the same names.

- **39 by webhook** (`triggers.ts`): one webhook per connection and repository. The connected account must be an admin
  of the repository, and a fine-grained token needs the Webhooks permission.
- **7 polled** (`polls/github.ts`), which GitHub has no webhook for: new followers, issues assigned to you, notifications,
  artifacts (two), new workflows, release assets.

Composio's "one specific object" triggers are the repository's event with a filter (`issue_number`, `check_run_id`...).
