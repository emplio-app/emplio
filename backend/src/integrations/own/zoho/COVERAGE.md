# Zoho CRM coverage

Source: Zoho's own OpenAPI files (github.com/zoho/crm-oas, v8, generated 2026-11-09 by `bun scripts/openapi-actions.ts zoho`). Every operation in them is an action, plus create/list/get/update/delete/search for Leads, Contacts, Accounts, Deals, Events, Tasks, Calls, Notes and Products under Composio's names.

## Left out

| What | Why |
| --- | --- |
| Record sharing (`/actions/share`) | Needs a separate `ZohoCRM.share.<module>.*` scope per module; add them per module if asked |
| Blueprint, webforms, access settings, connected workflow rules, Composio's validate_credential | Not in Zoho's published v8 spec |

## Sign-in

Sign in with Zoho only (no key). Scopes: see `SCOPES` in index.ts, broad families (`.ALL`) plus the separately named ones the spec asks for (mass actions, ownership, composite calls, Zia, files). Tokens last an hour and are renewed by `zohoOAuth`. `check` labels the connection with the signed-in CRM user.

## Hand adjustments

- Spec defaults stripped, so nothing is sent that wasn't asked for; upload fields typed as files.
- `get_related_records_count`, the COQL query and bulk search are POSTs that only read, so they run unasked.
- Bulk jobs go to `/crm/bulk/v8`, uploads to `upload.zoho.<tld>`, both through the login's data centre.
- Failures sent with a 200 (`status: error`, or every row of `data` failing) become errors; a dead login marks the connection expired, a scope mismatch doesn't.

## Triggers (polled, polls/zoho.ts)

new_lead, lead_updated, new_contact, contact_updated, new_deal, deal_updated (`<id>:<Modified_Time>` where it's "changed"). Each check looks at the newest 200.
